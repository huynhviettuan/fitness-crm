# 11 — Non-Functional Requirements

| Area | Requirement | Source |
|---|---|---|
| Platform | Web app; works well on phones; member mobile app later | brief §11, D-043 |
| Phone-first screens | Leads (list, Kanban, detail, quick add), PT calendar, session log usable at 360px | brief §6.1, §7.3, §12 |
| Language | Vietnamese UI, English ready (all strings in message files); customer emails in Vietnamese or English | D-043, D-036 |
| Formats | `dd/MM/yyyy`, 24-hour, gym timezone (A-001), VND whole đồng (A-002) | doc 23 |
| Configurability | Every admin value editable on screen, effective immediately, without a deployment | D-015, brief §12 |
| Multi-branch | All data and reports by branch; users limited to their branches | D-014 |
| Performance | Lists and the PT calendar respond within 1 s at the A-028 volume; reports within 5 s; Excel exports of up to 50,000 rows within 30 s (generated by the API) | A-028 |
| Availability | Business hours 05:00–23:00 every day; planned maintenance outside them | gym hours |
| Concurrency | Session consumption, overlaps, idempotent creates, and approvals are safe under concurrent requests | AGENTS.md §3 |
| Durability | Money and session changes are transactional; nothing is hard-deleted | D-034, D-035 |
| Auditability | Every change logged with before/after values; login history | T-048, D-017 |
| Backups | Automatic daily backups plus an independent daily copy; monthly restore test into staging | D-043 |
| Environments | Staging separate from production, each with its own database | D-043 |
| Security | Server-side authorization, hashed passwords, HTTPS, OWASP Top 10 tests | doc 12, doc 24 |
| Personal data | ID documents and health data encrypted, visible only to permitted roles, consent recorded, masked in exports where hidden | D-042 |
| Email delivery | Transactional provider from the gym's authenticated domain (SPF, DKIM, DMARC); each email's status stored | D-036 |
| Accessibility | Keyboard operable, WCAG AA contrast, status never shown by color alone | doc 23 |
| Maintainability | Popular technology (TypeScript, Next.js, NestJS, PostgreSQL), documented API (OpenAPI), owner-owned repository and accounts | D-043, T-041 |
| Extensibility | Modules and tables designed so ERP modules and devices can be added without rewrites | D-013 |
| Data migration | GymMaster import reconciles customer count, contract value, paid, and sessions left before cut-over | D-039 |
